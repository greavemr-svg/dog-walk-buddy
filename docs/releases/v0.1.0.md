# Dog Walk Buddy v0.1.0

First release (MVP), Android phones only (minSdk 29, targetSdk 36), English (UK). Run `20261019-dog-walk-buddy-mvp`, epic #7.
Spec: `docs/specs/20261019-dog-walk-buddy-mvp.md`. Design: `docs/design/20261019-dog-walk-buddy-mvp.md`. ADRs 0001-0005 in `docs/adr/`.

## Version choice
0.1.0 (versionCode 1): first release, nothing to compare against, so there is no commit-driven bump. `version.properties` already held 0.1.0 and is unchanged. It is kept below 1.0.0 because the reference-phone checks below are still outstanding. Moving to 1.0.0 is the owner's decision.

## What's new
- **Walk check:** a one-glance Go / Caution / Avoid rating from MET Norway forecasts, with the best window in the next 12 hours. It uses approximate location and a cached check, and an "About this advice" screen names the guidance sources. Advice is guidance, not veterinary advice.
- **Dog profile:** one dog with name, breed, photo and a heat-sensitivity setting (Normal / Sensitive) that makes heat warnings stricter.
- **Walk recording:** start and stop in one tap, works offline, records duration, distance and GPS route through a foreground service.
- **History:** walk list, weekly totals (walks, time, distance) and delete.
- **Walk detail:** the route drawn on a street map.
- **Privacy:** a Privacy screen and "Delete all my data".
- **Accessibility:** large touch targets, bright-sunlight theme, TalkBack labels.

## Fixes
- Walk detail map: MapLibre logo and attribution button kept visible (#26, PR #27).

## Privacy
- Location, walks and the dog profile stay on the device. No accounts, no backend, no analytics or tracking. Backup is disabled (`allowBackup=false`).
- Weather requests go to `api.met.no` over HTTPS with coordinates rounded to 2 decimals and an identifying User-Agent.
- Map tiles come from `tiles.openfreemap.org`. The tile server sees the IP address and the tile coordinates viewed. Tile requests carry only the app User-Agent.
- Photos are re-encoded without EXIF and stored privately.
- Permissions: 7, none for background location.

## Known issues and residual items
Owner decision: "Emulator now, phone after release". These checks on the reference phone (Samsung Galaxy A35 5G) are **not yet done**:
- Real pocket walk with screen off and doze (AC29, AC31).
- TalkBack speech, including the "Normal" radio button label (AC50).
- Real gallery photo (AC43).
- Device-to-device transfer and restore (AC48).
- User-Agent seen through mitmproxy (AC49).
- Battery drain over 60 minutes (target 8% or less).
- Check time over 4G, 20 runs (emulator: 8 runs on broadband, median 1.75 s).
- All reference-phone performance figures. History with 500 walks measured p90 964 ms on the emulator against the 1 s limit, so it is close and must be re-measured on the A35.

Open Low and cosmetic items:
- S-01: an in-flight cached check row can be saved after "Delete all".
- S-02: a second, concurrent delete is possible after leaving and re-entering Privacy (worst case a spurious failure message).
- S-03: Dependabot covers only GitHub Actions, not Gradle. Owner to add it by governance PR. S-04 (minified release build) is closed by the release-build smoke test.
- A recovered walk shows a 0:00 duration.
- At maximum font size and maximum display size the attribution box overlaps the MapLibre logo.
- The h:mm duration format is ambiguous for short walks (no label).
- The walk detail map roughly doubles memory (PSS about 165 MB against 85 MB without the map). The spec sets no limit.
- The release build is unsigned unless `DWB_KEYSTORE_*` environment variables are set. Publishing to Google Play is a manual owner action.

## Upgrade and rollback
- Upgrade: first release, there is no earlier version. Room schema version 1 (`app/schemas/`), so there are no migrations. `fallbackToDestructiveMigration` is forbidden by ADR 0004, so future changes need tested `Migration` objects.
- Rollback before shipping: close the release PR without merging. After shipping: revert the release merge commit on `main` through a revert PR and issue a new build. Users can reinstall a previous build. Because the data is local-only and the schema is version 1, there is no data migration to reverse. Uninstalling removes all app data.
