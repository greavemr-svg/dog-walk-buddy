# ADR 0004: Local data model, persistence (Room) and backup exclusion

- Status: Accepted
- Date: 2026-10-19
- Run: `20261019-dog-walk-buddy-mvp`

## Context
The app stores walks with GPS routes (personal data), one dog profile with a photo copy, and the last check result. All of it lives on the device only (spec, Data and privacy).

The storage must:
- survive the app process being killed mid-walk (AC34)
- open 500 walks of history in 1 s or less (NFR)
- support deleting one walk (AC40) and deleting everything (AC47)
- re-rate the cached check when sensitivity changes without a network request (AC44)
- be excluded from cloud backup and device transfer (AC48)

A schema is hard to change after release.

## Options considered
1. **Room (SQLite) for all structured data, and a file for the photo.**
   - Pros:
     - Transactions (finalise a walk, delete all).
     - Indexed queries.
     - Flows for reactive UI.
     - Foreign-key cascade deletes route points.
     - Exported schema for migration tests.
   - Cons: KSP annotation processing.
2. **DataStore (Preferences or Proto) plus JSON files for routes.**
   - Pros: simple.
   - Cons: no transactions across walks and points, whole-file rewrites on every GPS fix (bad for AC34 and battery), and slow aggregation over 500 walks.
3. **SQLDelight.**
   - Pros: SQL-first.
   - Cons: less mainstream on Android, and a third-party Gradle plugin on AGP 9.

## Decision
Room 2.8.4, database `dog_walk_buddy.db`, schema version 1, `exportSchema = true` into `app/schemas/`. All times are stored as UTC epoch milliseconds. Grouping and display use the injected device `ZoneId`.

| Table | Columns | Notes |
|---|---|---|
| `walk` | `id` INTEGER PK autoincrement; `start_utc_ms` INTEGER NOT NULL; `end_utc_ms` INTEGER NULL; `status` TEXT NOT NULL (`RECORDING`, `COMPLETE`); `distance_m` REAL NOT NULL DEFAULT 0; `last_fix_utc_ms` INTEGER NULL | Index on (`status`, `start_utc_ms`). History reads only `COMPLETE` rows and never loads route points. |
| `route_point` | `id` INTEGER PK; `walk_id` INTEGER NOT NULL FK → `walk.id` ON DELETE CASCADE; `seq` INTEGER NOT NULL; `lat` REAL; `lon` REAL; `accuracy_m` REAL; `time_utc_ms` INTEGER | Index on (`walk_id`, `seq`). Each accepted fix is inserted, and `walk.distance_m` and `walk.last_fix_utc_ms` are updated, **in one transaction**. A process kill loses at most the fix in flight (AC34). |
| `dog_profile` | `id` INTEGER PK (always 1); `name` TEXT NOT NULL; `breed` TEXT NULL; `photo_file_name` TEXT NULL; `heat_sensitivity` TEXT NOT NULL DEFAULT `NORMAL` | A single row. No row means no profile, so Normal is used (AC45). |
| `cached_check` | `id` INTEGER PK (always 1); `fetched_utc_ms` INTEGER NOT NULL; `lat` REAL; `lon` REAL (the rounded coordinates); `hours_json` TEXT NOT NULL | `hours_json` is the validated, provider-neutral `List<HourlyConditions>` serialised with kotlinx.serialization. **Raw conditions are stored, not the rating**, so a sensitivity change re-rates without a network request (AC44). Replaced on each successful check. Ignored when it is 3 h old or older (AC21, AC22). |

Other storage decisions:
- **Photo:** the picked image is decoded with a size bound (it is refused over 20 MB or 8000 px on a side), downscaled to at most 1024 px on its long edge, and re-encoded as JPEG to `filesDir/profile/photo_<uuid>.jpg`.
  - Re-encoding strips EXIF, including GPS.
  - The file name is generated by the app, never taken from the content URI.
  - Replace writes the new file, commits the row, then deletes the old file. Remove deletes the file and nulls the column (AC43).
- **Recovery (AC34):** at app start, `RecoverInterruptedWalkUseCase` finds any `RECORDING` walk when no recording service is live in the process. It sets `end_utc_ms = last_fix_utc_ms ?: start_utc_ms` and `status = COMPLETE`. `distance_m` already holds the distance up to the last fix.
- **Delete one walk (AC40):** deletes the `walk` row in a transaction. The cascade removes its points.
- **Delete all (AC47):** stops any active recording, then:
  - `clearAllTables()`
  - deletes `filesDir/profile/`
  - evicts the OkHttp weather cache
  - clears the MapLibre ambient cache
- **Migrations:** version 1 has no migration. Future schema changes need explicit `Migration` objects and a `room-testing` migration test. `fallbackToDestructiveMigration` is **forbidden**, because it would silently delete walk history.
- **Backup exclusion (AC48):**
  - `android:allowBackup="false"`
  - `android:fullBackupContent="@xml/backup_rules"` (for API 29-30) excludes the `root`, `file`, `database`, `sharedpref` and `external` domains.
  - `android:dataExtractionRules="@xml/data_extraction_rules"` (API 31+) excludes every domain under both `<cloud-backup>` and `<device-transfer>`.
  - On Android 12+, `allowBackup="false"` alone does not stop device-to-device transfer, so both are needed.
- **Encryption at rest:** none beyond Android file-based encryption (spec Assumption 12). The data is not health or employment data. The security review may recommend more.

## Consequences
- Room gives typed DAOs and Flows. History aggregation (weekly totals) is pure Kotlin over `WalkSummary` rows, so it is unit-testable (AC36, AC37).
- Reversal: the data is local, so a different store needs a one-off migration on upgrade. The `exportSchema` JSON documents the exact shape.

## For new dependencies
- Licence: Room Apache-2.0.
- Maintenance: Google. 2.8.x gets patches. Room 3.0 (`androidx.room3`) moving to stable later is a future, deliberate migration.
- Known vulnerabilities: none known.
- Size / performance impact: about 300 kB. Inserting one route point roughly every 3 s is negligible.
